# Planning and questions

Use **Plan** beside the approval selector to explore and design before implementing. Planning is separate from approval policy. The resulting checklist and handoff brief are saved with the thread and survive restart. Native status updates tick off completed steps; ending a turn does not imply that every step completed.

**Start fresh from plan** creates an independent thread in the same workspace. Choose any enabled provider/model in the composer, then send to begin. It carries the saved brief and checklist, not the old messages, activity, or provider session ID. The original thread is retained. A worktree is reused rather than replaced or checked out again. The brief should include goals, constraints, decisions, files and validation; attached source material is not automatically copied into the new context.

Question cards support single/multiple choices, optional custom text, submit and skip. Nothing is submitted just by selecting an option. Pending requests survive renderer reloads, belong to the originating thread, and are cleared on run cancellation/completion. They do not survive app restart.

## Provider integration

- Codex: native `collaborationMode`, `turn/plan/updated`, plan items and `item/tool/requestUserInput`. Planning forces read-only sandbox permissions. Execution explicitly returns to default collaboration mode. The app also exposes `vulp_update_plan` for a durable implementation brief.
- Claude: SDK plan permission mode, `AskUserQuestion` through `canUseTool`, `TodoWrite` updates, and `vulp_update_plan`. ExitPlanMode does not silently start execution; implementation is a separate user action.
- Cursor: advertised ACP plan mode, `cursor/ask_question`, `cursor/create_plan`, `cursor/update_todos`, and ACP plan updates. Cursor questions accept the provider's option IDs; its current response schema does not provide a free-text answer field.
- Other ACP providers: structured plan updates are displayed. Plan mode is used only when advertised by the provider; unsupported modes fail explicitly. No generic ACP question API is assumed.

Protocol references: [OpenAI App Server](https://learn.chatgpt.com/docs/app-server), [Cursor ACP](https://prod.cursor.com/docs/cli/acp). Codex payloads were also checked against TypeScript bindings generated by the installed CLI. Claude integration uses the installed Agent SDK types.

## Validation

- `pnpm typecheck`, `pnpm test`, `pnpm build`.
- `env -u ELECTRON_RUN_AS_NODE J2CODE_VIRTUAL_DISPLAY=1 node scripts/smoke-planning.mjs`: real Electron/preload/IPC/store, fixture providers. Covers question rehydration, answers, saved checklist, fresh-context cross-provider execution, persistence and mobile layout. This is software-rendered X11 proof, not native GPU proof.
- `node --import tsx scripts/check-live-planning.mts [codex|claude]`: live, authenticated question/answer and plan smoke in an isolated temporary workspace.
